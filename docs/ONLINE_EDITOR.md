# 在线写作 / 日记编辑 完整说明书

本说明覆盖 `/write`（导航栏「写作」）页面的**字段含义、使用方式、以及发布后发生了什么**。附带 Markdown 语法速查和常见问题。

---

## 一、这个功能是什么

`/write` 页面让你不用打开代码编辑器，就能在网页上写文章、写日记。后端是 Vercel 的 Serverless 函数，用一把**细粒度 PAT** 代你把内容提交到 GitHub 仓库。你的浏览器从头到尾不接触 GitHub 凭证。

---

## 二、文章保存到哪里？（slug 与 .md）

**slug 就是文章的文件名，也是网址的一部分。**

| 你填的 slug | 保存成的文件 | 文章网址 |
|---|---|---|
| `my-first-post` | `src/content/posts/my-first-post.md` | `/posts/my-first-post/` |

- 文章是**以 `.md`（Markdown 文本文件）形式保存在 GitHub 仓库里的**，不是数据库。
- slug 输入框末尾那个灰色的 `.md` 是**固定提示**，表示文件会以 `.md` 结尾保存，你**不用输入它**，只填前面的文字。
- slug 建议用英文、小写、短横线连接（如 `my-first-post`），不要用空格或中文。

## 三、字段详解（含例子）

### 核心字段（默认就能看到）

| 字段 | 作用 | 例子 |
|---|---|---|
| **标题** | 文章大标题，必填 | `我的第一篇博客` |
| **slug** | 文件名 + 网址，必填 | `hello-world` |
| **发布日期** | 文章发表时间，格式 `YYYY-MM-DD` | `2026-08-21` |
| **封面图路径/URL** | 文章列表页显示的封面。可填相对路径或完整网址 | `./cover.png` 或 `https://.../a.jpg` |
| **分类** | 文章分类，一个 | `技术` |
| **标签** | 逗号分隔，多个 | `Markdown, 前端, Astro` |
| **摘要** | 一句话描述，显示在列表 | `这篇讲我怎么搭博客` |
| **草稿（隐藏）** | 勾选后文章发布但不显示（前端会过滤 draft） | 勾选 = 隐藏 |
| **置顶** | 勾选后文章排在最前 | 勾选 |
| **置顶优先级** | 多篇置顶文章之间的顺序，**数字越小越靠前**，只对置顶文章生效 | `1`、`2`、`3` |
| **允许评论** | 是否开启评论区 | 默认勾选 |
| **语言** | 文章语言 | `zh` 或留空 |

### 高级字段（点「展开高级字段」）

| 字段 | 作用 | 例子 |
|---|---|---|
| **permalink** | 给文章一个**根路径**的短网址（不带 `/posts/`），优先级最高 | 填 `about-me` → 网址 `/about-me/` |
| **alias** | 给文章一个 `/posts/` 下的**备用网址** | slug 是 `my-post`，alias 填 `old` → 多一个 `/posts/old/` |
| **作者** | 显示的作者名 | `soyonu` |
| **许可证名** | 文章许可证 | `CC BY-SA 4.0` |
| **加密文章** | 勾选后文章需要密码才能查看 | 勾选 |
| **密码** | 加密文章的查看密码 | `123456` |
| **密码提示** | 提示读者密码是什么 | `生日` |

> 日常写文章，`permalink`、`alias`、`作者`、`许可证`、`加密` 都可以留空，完全不影响使用。

## 四、Markdown 语法速查

编辑器是纯文本输入框，**需要按 Markdown 语法写，不会自动把自然语言转成格式**。但提供快捷键帮你补符号，以及「预览」按钮看效果。

| 想写什么 | 语法 | 效果 |
|---|---|---|
| 一级标题 | `# 标题` | 大标题 |
| 二级标题 | `## 小标题` | 次标题 |
| 加粗 | `**粗体**` | **粗体** |
| 斜体 | `*斜体*` | *斜体* |
| 无序列表 | `- 项目` | 圆点列表 |
| 有序列表 | `1. 第一` | 数字列表 |
| 链接 | `[文字](网址)` | 超链接 |
| 图片 | `![描述](图片地址)` | 图片 |
| 行内代码 | `` `code` `` | `code` |
| 代码块 | 三个反引号包住多行 | 代码块 |
| 引用 | `> 引用内容` | 引用框 |
| 分割线 | `---` | 横线 |

**快捷键**（光标在正文里时）：

- `Ctrl/Cmd + B`：插入加粗
- `Ctrl/Cmd + I`：插入斜体
- `Ctrl/Cmd + K`：插入链接

**粘贴图片**：直接 Ctrl+V 粘贴一张图，会自动上传并插入 Markdown 图片语法。

## 五、发布后发生了什么（GitHub 与 Vercel 的关系）

```
点「发布」
  → 后端用 PAT 把文章提交到 GitHub 仓库（src/content/posts/<slug>.md）
  → GitHub main 分支多了一个 commit
  → Vercel 检测到 main 有更新 → 自动重新构建部署
  → 约 1 分钟后，云端网站显示新文章
```

**要点：**

1. 发布 = **直接写 GitHub 仓库**，效果在云端网站。
2. **本地文件夹不会自动同步**。你本地 `D:\blog\my-astro-blog-bak` 是另一份拷贝，要看云端新文章需手动：
   ```bash
   cd D:/blog/my-astro-blog-bak
   git pull
   ```
3. **以后本地改代码 `git push` 到 GitHub，Vercel 会自动构建，不用手动管它。** 只有构建失败（红色报错）时才去 Vercel 面板看日志。

## 六、日记怎么用

日记标签页里直接写，字段：

| 字段 | 作用 |
|---|---|
| 正文 | 日记内容，必填 |
| 心情 | 可选，如 `开心` |
| 位置 | 可选，如 `北京` |
| 标签 | 逗号分隔 |
| 图片 | 一行一个图片 URL |

日记数据存在 `src/data/diary.json` 里，和文章一样，发布后提交到 GitHub 并触发 Vercel 重新构建。

## 七、常见问题

### Q1：PAT 一年过期是什么意思？
PAT 是后端用来代替你提交 GitHub 的令牌，GitHub 规定**最长 1 年有效**。到期后点「发布」会失败。解决：重新生成一个 PAT（步骤同首次配置），更新 Vercel 的 `GH_PAT` 环境变量，Redeploy 即可。**不用改代码，密码和页面都不受影响。**

### Q2：本地文件没变，是不是没保存成功？
不是。发布是写**云端 GitHub**，不是写本地。判断是否成功看 GitHub 仓库网页版或云端网站，而不是本地文件夹。本地想看就 `git pull`。

### Q3：导航「写作」的图标怎么加？
图标已填好，是 iconify 的笔图标，位置在 `src/config.ts` 的 `navBarConfig.links` 里：
```ts
{ name: "写作", url: "/write/", icon: "material-symbols:edit" },
```
想换图标就改 `icon` 的字符串（格式参考同文件的 `"material-symbols:book"`）。注意：导航图标是 **iconify 在线图标**（字符串名），不是本地图片文件。

### Q4：本地开发时编辑器报错？
本地 `pnpm dev` 时后端 `/api/*` 不存在（Vercel 专属），登录/发布会失败，属正常。完整联调需 `vercel dev`。

## 八、一次性配置（首次部署前做一次）

下面 5 个环境变量要配到 Vercel，其中**登录密码**是最常用到的，单独讲。

### 8.1 设置登录密码（3 步）

**第 1 步：生成密码 hash**

在电脑终端（项目目录下）执行：

```bash
cd D:/blog/my-astro-blog-bak
pnpm hash-password "你想用的密码"
```

会输出一行 `scrypt$...`，复制这整行。（密码不会以明文存，存的是这串 hash，别人看到也推不出你的密码。）

**第 2 步：填到 Vercel**

打开 Vercel → 你的项目 → **Settings** → **Environment Variables**，新增一个变量：

| Key（名称） | Value（值） |
|---|---|
| `EDITOR_PASSWORD_HASH` | 第 1 步生成的那行 `scrypt$...` |

环境勾选 **Production**（和 Preview）。

**第 3 步：Redeploy**

保存后点 **Redeploy**（或等下次自动构建）。之后访问 `/write/`，输入「你想用的密码」即可登录。

> **改密码**：重新跑第 1 步生成新 hash → 更新 Vercel 的 `EDITOR_PASSWORD_HASH` → Redeploy。其他不用动。

### 8.2 其余环境变量

| 名称 | 值 |
|---|---|
| `GH_PAT` | Fine-grained PAT（Contents: Read & write，限本仓库） |
| `SESSION_SECRET` | 随机长字符串（`openssl rand -hex 32` 生成） |
| `GITHUB_OWNER` | `soyorinloves` |
| `GITHUB_REPO` | `my-astro-blog` |
